# Chat framing preferences ownership

The exact `/api/chat-framing/preferences` route is permanently native for GET/PUT and unsupported-method responses. The existing Account authentication, origin/CSRF and device policy precede method refusal. PUT keeps both preference keys, strict booleans, partial merging, compact key order and public errors from Core's original route. Existing chat and reasoner readers continue to read the same per-user file without a cache. No suggestion, model execution, admin settings or mirror scheduling is moved here.

The final gate, legacy initialization and read/merge/replace run under the existing SQLite IMMEDIATE writer transaction, with no nested writer lock. A header-only gate runs before PUT body polling; GET and unsupported methods never consume their bodies. Actual PUT transport failure retains the original framing error. Public Account entry samples a trusted live clock after body/lazy-account initialization, anchors monotonic time before that sample, and carries it through all initial authentication and writer waits; expiry is checked again after bounded legacy initialization. This serializes live account writers and partial preference updates. It is not a crash-atomic transaction across SQLite and the filesystem; a later failure cannot be called success. No request body chooses a tenant or path.

Linux production reuses the established workspace/legacy-claim primitives as a target-specific existing dependency, with no new crate versions. Non-Linux account tests operate only on initialized synthetic workspaces; missing-workspace initialization refuses there. Linux initialization/legacy tests and actual front routing remain mandatory CI evidence. Portable tests do not establish those results. The old Node writer is frozen under Core's test-only oracle directory, absent from production exports/bindings, and Node bypass routes refuse all methods unconditionally. No release pin, activation or deployment follows from source ownership.

The reader projects only the two recognized keys after whole-input lexical JSON validation with serde IgnoredAny. Ignored strings and numbers are not decoded through narrower Rust Unicode/f64 types. This preserves Node behavior for lone-surrogate escapes, literal private-use scalars, ignored numeric overflow, deep ignored values, duplicate and escaped keys. The original failing surrogate case remains in the independently generated corpus; expected values come only from the unchanged Core reader/route/http helpers. The projection is endpoint-specific, not a replacement general JSON implementation.
