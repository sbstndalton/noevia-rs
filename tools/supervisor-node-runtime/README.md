# Candidate Node 22 consumer correction

This directory contains the candidate recipe for the supervisor's strict TCP qualification. Required CI downloads, builds and verifies an unqualified candidate on an exact-key cache miss. It does not install or activate a runtime in production, and is not a qualified runtime or an instruction to change selected release inputs.

The preserved Linux regression observed Node 22/libuv 1.51.0 emit EOF after EPOLLIN|EPOLLERR|EPOLLHUP and a positive short read, without a kernel zero read. Upstream libuv commit [2e2114ed](https://github.com/libuv/libuv/commit/2e2114ed8957a0124bc629c61d034c387b8ce42a) removes that EOF shortcut when POLLIN is present. The patch here contains only its two runtime-file changes, rebased onto exact Node 22.23.4 source context; upstream PTY tests are not a substitute for the unchanged TCP and image tests. Upstream attribution/license are preserved.

`source-lock.json` records the official source archive/checksum, upstream commit, exact patch bytes, both runtime pre/postimages and the resolved Linux/amd64 Bookworm builder image. The reference tag is documentation; a future build must use the immutable platform digest. This is an additional maintained runtime artifact, not an assertion that a version string identifies the correction. No other architecture/libc is covered.

A build recipe still needs exact review before compilation: fail closed on source/patch/preimage mismatch, offset/fuzz/partial application, extra changed files or remaining READ_PARTIAL references; finite two-job compilation; configuration/library parity against the same unmodified Node 22.23.4 reference; binary hash and source/patch/toolchain/configuration provenance; exact matching Node/npm assets and licenses. The intended full-ICU configuration in the lock is a candidate, not verified parity. Never regenerate frozen oracles to absorb runtime drift.

The first actual candidate proof must preserve complete 64 MiB with normal EOF and paused incomplete-output reset. The shipped Debian web client and Debian slim sandbox must use the same provenance-bound correction contract. The 32-case driver must run the real ACP caller in the actual corrected assembled web runtime image and the supervisor in its actual sandbox image. Existing Alpine build stages remain unchanged; a glibc binary cannot be copied into them. All relevant existing frozen differentials, required checks, rollback/provenance and independent review gates remain. The recorded uncorrected failure remains evidence. No runtime fallback, acceptance relaxation, production activation or deployment is supplied here.

## Candidate finite recipe

`runtime.py` implements bounded official-archive download, exact link-free extraction, atomic two-file patch validation/application, a source-evidence-bound configuration comparison and strict runtime checks, compiler/library provenance, and artifact/cache verification. Node's own `tools/js2c.cc` pseudo-Boolean conversion is mirrored when comparing `config.gypi` with `process.config`; no behavioral configuration fields are ignored. Any actual mismatch requires investigation.

`ci.sh` is restricted to owned GitHub Linux amd64 qualification. It pulls the immutable builder manifest, verifies its locked image configuration identity, then compiles in one non-root, network-disabled, read-only-root container with two CPUs, six GiB RAM/swap ceiling, dropped capabilities and a finite deadline. Only its uniquely named container is cleaned on exit. The build's work/output are confined to its own temporary directory; no runtime is installed on the runner or a production host. The existing Node22 workspace oracles retain their input; only the mandatory supervisor reader/producer fixture uses the explicitly verified candidate path. All original byte/reset/EOF assertions and timing remain.

The exact-key scoped CI cache includes the six actual recipe inputs (`runtime.py`, `ci.sh`, lock, patch, builder manifest, assembler evidence), has no restore prefixes, and must pass binary/source/builder/license/configuration checks before execution. Documentation or portable-test edits do not repeat an unchanged C++ build. This is a trusted scoped CI cache, not a signed release artifact or proof against arbitrary cache tampering. Its artifact identity is still subject to independent result review and actual shipped-image qualification. Named provenance/configuration/compile logs are retained by CI for three days; no candidate binary is published by the upload step.

This complete candidate recipe still requires exact review before its first Linux compilation. No build, corrected-runtime pass, image pairing or activation is established by portable refusal checks.

The vendored `builder-manifest.json` hashes to the exact pulled platform digest and binds its config digest. Image inspection accepts only that exact platform-manifest ID (containerd store) or its exact config ID (classic store), alongside the same required repository digest and Linux/amd64 platform. Unexpected identities still refuse. The raw inspection is retained before this check so refusal has actual diagnostic evidence; no success receipt is produced on failure. Docker containerd identity semantics: https://github.com/moby/moby/blob/master/daemon/containerd/image_inspect.go.

## One evidenced assembler-discovery difference

The actual pinned Bookworm configure result differed from the official Node binary in GAS discovery (2.40 versus 2.35) and an empty release URL. The recipe now supplies the real official release URL option and observes process.release. It does not ignore that API difference.

`gas-metadata-evidence.json` binds every regular-member gas_version reference in the exact source archive, relevant generator/build sources, and their version predicates. For this one source/builder/platform, reference 2.35 and builder 2.40 make the same relevant assembly-source decisions. Normal make-node uses checked-in generated assembly; the separate gen-openssl target is not selected. This is not a claim of bit-identical assembler output or generic compiler neutrality.

The comparator permits ONLY that directional field/value pair after source/evidence binding. Both raw snapshots remain truthful; the report explicitly says raw configuration equality is false. All other keys/types/values remain strict. Actual compiler-selected assembler/linker paths, versions and hashes are recorded. Post-compile process.config must equal the complete actual configured data, including GAS 2.40; all reference/candidate versions, features, release properties and crypto capabilities must match. A changed pair/source/builder/evidence or additional drift refuses.

Five unchanged upstream Node crypto scripts (hash, HMAC, explicit cipher/decipher, authenticated encryption, async sign/verify) run on both actual reference and candidate binaries with fixed source hashes and finite deadlines. A skipped or failed script cannot earn PASS; binary/source/log hashes identify each run. These are supporting checks, not comprehensive Node/OpenSSL or application qualification. The compiler deadline is reduced to 130 minutes, leaving time inside the unchanged 165 minute outer boundary for configure, both crypto runs and cleanup. The original TCP, full 32-case, actual web and sandbox, and frozen differential requirements remain unchanged. The updated complete recipe requires exact review before any next compilation.
