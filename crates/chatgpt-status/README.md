# Private M6 ChatGPT status policy checkpoint

Refs noevia #1373. This standalone crate is **not an integrated route** and is not a full M6 delivery. The parent workspace, server auth/store/router, corpus, core, supervisor and release files are untouched. Only `crates/chatgpt-status` is owned here.

Implemented: pure disconnected/reconnect/connected status policy; actual masked UTF16 email; arbitrary truthy JSON plan; duplicate-last object members; JS integer-key order; numeric overflow to infinities serialized as JSON null; bounded UTF16 JSON parser and iterative response emission; bounded startup current/previous key snapshot; fd-relative nofollow root components and regular key files; cancellation and two-second CPU deadline checks. `Service::read_with` checks product false before invoking the supplied read closure. That callback is not an implemented SQLite boundary and makes no SQL/auth ownership claim.

Reuse: secret-envelope is directly used for AES-GCM/current-previous/v1-v2 behavior, policy-leaves for JS trim, js-json only for the existing reviewed ECMAScript number formatter. Its existing parser/slice are unsuitable for this status contract because they refuse lone surrogates and numeric overflow. No changes to these dependencies. Keys never call the unbounded SecretKeys::load. Native startup snapshots keys exactly like actual Node createSecretStore; external replacement requires coordinated restart. It creates no key, folder or schema. Regular mounted-filesystem startup I/O is not forcibly cancellable; standard capped allocation is not a hard OOM/RSS guarantee.

Limits: user ID 4096 bytes, row ciphertext 256 KiB, state 64 bytes, replacement-decoded plaintext 192 KiB, JSON 8192 parsed nodes/65536 total string/key UTF16 units/64 recursive parse frames/4 Mi operation work budget, response 256 KiB. Duplicate hash probing is bounded by that cumulative work budget; four fixed radix passes order integer keys. Parse depth is explicitly capped recursion, with iterative output; drop recursion is bounded by the same accepted depth. Root/path 4096 bytes/128 components; fixed 33-byte file read with 64 syscall attempts, accepted key length exactly 32; previous env capped at 4096 bytes before trim/decode. Refusals are stricter than unbounded Node and are intended sanitized 502 at the future HTTP adapter. Ordinary decrypt/malformed JSON remains reconnect.

The CPU control checks before/after the existing bounded AES primitive, at parse/string/probe/emission boundaries, and at the read callback boundary. It spawns no worker. Caller must retain its worker/admission lease through callback, parse, cancellation and completion. It does not prove SQLite cancellation or a hard wall-clock bound on OS scheduling, startup file I/O, allocation or upstream primitive internals.

Qualification uses actual pinned core `010735c7d86d30269ab3f4a351b2135faea1c8e7` via its exported createChatGptOAuth/createProviderRoutes and actual JS envelope implementation. Tiny `tests/oracle.cjs` supplies fake DB/collaborators and only records actual answers/trace. Constructor DDL is recorded only in fake setup; status read/write/network/audit collaborators reject unexpected calls. `node-status.v1.json` binds full source SHA256, seam SHA256 and actual checked Node22.23.3. Its 293 cases include generated UTF16/duplicate/number-bit cases, lone surrogates, overflow, integer key ordering, mask boundaries, malformed values, v1/v2/current/previous/wrong user, invalid UTF8 replacement, feature false and ordinary SQL error mapping at the factory route. Encrypted fixture bytes are random because actual Node encrypt supplies its nonce; regeneration is semantically replayable but not byte-identical ciphertext regeneration. The explicit invalid-UTF8 envelope alone is generated by existing Rust seal, then opened/shaped by actual Node.

Tests include the generated tenant property, startup snapshot vs restart, root/key symlink, FIFO/directory, wrong/missing key lengths, previous-file precedence/env encoding, and named limits. Six actual source mutations must fail the named semantic assertion: first @; Unicode replacement instead of first UTF16 unit; string-only plan; duplicate-first; wrong user binding; missing key NOFOLLOW. Existing c665 bounded process and mutation classifier tools are reused by path for all Git/Node/mkfifo/mutant subprocesses; failed compile/timeouts/unrelated panics are not counted as mutation proof. The mutation example edits and restores only this crate's owned source; don't run concurrently with another writer.

## Private SQLite checkpoint (#1373)

`SqliteService` accepts a fixed absolute data directory, startup previous-key/env
configuration and an **already authenticated** owner. It never owns HTTP routing,
authentication, schema initialization or the Node feature cache. The future adapter
must still supply the bounded Store/auth gate, ownership default OFF, exact GET route,
Node feature refresh and supervisor integration; those shared files are held.

Each admitted request opens a fresh READ_ONLY/NOFOLLOW connection on its worker.
Global admission spans service instances (8 including synchronous startup), with
one owner lease and at most 2 seconds before admission; saturation refuses immediately.
The request SQL/CPU budget is 2 seconds and approximately 2 million VM operations,
with immediate busy refusal. Jobs are joinable and their leases survive cancellation,
HTTP abandonment, errors and shutdown until thread join confirms completion. Job drop
and service shutdown join workers; neither promises a hard wall-clock return when
kernel I/O stalls. Connections are never reused, preventing late interrupts from
reaching another request. SQLite limits are configured before application schema SQL.

Keys retain the existing startup snapshot contract. Product false skips all OAuth
metadata, row reads and decryption. Base metadata queries are restricted to settings
and migrations; the 256-object / 1 MiB aggregate schema scan runs only after product
true. Fresh connections revalidate their read snapshot every time, without schema or
statement caches. PK/index collation is proved BINARY, and actual nullable TEXT PK
DDL is accepted while runtime NULL keys/owners are refused.

Named qualification differences: owner ≤1024 UTF8 bytes; ciphertext ≤262144 bytes,
state ≤64 bytes; nontext/oversized runtime fields, NULL PK rows, incompatible/extra
schema columns/index qualification and metadata/resource failures refuse as sanitized
unavailable (future HTTP502). Node may accept/coerce/reconnect for some such values.
Arbitrary bounded plan values remain intact; named OAuth tokens are not projected.

The directory and pathname parents must remain operator-controlled and stable.
Retained Root checks reject detectable root/DB changes and symlink/nonregular DB or
companions; ordinary SQLite VFS canonicalizes paths and is **not** anchored to that
FD. Concurrent adversarial rename races are outside this qualified deployment
condition. Existing Node-created WAL/SHM are required; no companion/folder repair.
SQLite may bookkeep SHM locks/read marks despite read-only database access. This
is no application/database mutation, not a promise of zero write syscalls.
Standard allocator OOM, SQLite automatic schema allocation and uncancellable
regular-file open/read I/O remain limitations; cache size is not a hard RSS cap.

Focused local evidence uses synthetic state only: actual pinned core010735 factories,
Node22.23.3 and compatible cached better-sqlite3 for 14 real database cases; new
integration/unit/property tests and semantic SQLite mutants. The historical293 pure
policy cases were not rerun. Linux CI, whole front/auth/feature corpus and distinct
Sol6.1HIGH exact security review remain required before publication/integration.

Run focused checks serially (`--test-threads=1`): global owner admission is intentionally
shared across fixtures. `examples/sqlite_oracle.rs` validates the pinned source and
runtime and records source/addon/seam hashes; pass the compatible cached dependency
path explicitly. All its child processes and mutant commands use the existing bounded
Rust qualification process seam. Never run the actual app to build fixtures.

Application-query qualification: while false, no explicit OAuth schema/token
projection or decrypt occurs. SQLite open/schema machinery can still internally
read/parse all schema; no claim excludes physical OAuth sqlite_schema bytes.

## Private exact mutation certificate (#1374)

The SQLite runner uses its own source-bound classifier; shared qualification tools
and all SQLite/key/policy/fixture source remain unchanged. Each selected failure is
bound to a unique current assertion statement, its owning test, exact source hash,
path, dynamically derived line/column, assertion kind and expected payload. The two
VM assertions share an ID but have separate concrete allowed sites; the pre-copy
loop has one concrete site for its two field iterations. Another site with the same
ID is refused. Compiler/setup/unwrap, extra panic/test/failure inventories, wrong
source/policy/location, exit/capture limits and process errors cannot certify a kill.

Run `sqlite_mutants -- /absolute/fresh-evidence-directory` for the complete seven-case
matrix. Incremental start mode is removed. The runner preserves bounded raw captures,
exit/error metadata, full mutated/assertion source copies, hashes and exact restoration.
A final seven-entry certificate is created only after all captures match current source
and their intended concrete assertions. `sqlite_mutants -- --certify /absolute/evidence`
recertifies preserved captures without spawning test processes; it reconstructs each
expected mutant from current unchanged guard source and requires byte/hash equality.
Rust's empty nocapture failure-details section is allowed only before the single exact
final failure inventory. This is semantic qualification evidence, not route/publication
or production integration approval.
