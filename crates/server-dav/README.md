# Inbound Diary DAV source slice

This crate is a source-only HTTP contract. It has no binary, application route, listener, production backend, image packaging or deployment switch. DenyAll is the only included Backend implementation. Node's inbound listener remains authoritative and this crate does not claim production DAV parity or retire Node.

The current Node reference is noevia-core server/dav.cjs, dav-settings.cjs, dav-ops.cjs and their real-HTTP synthetic tests. The existing noevia-rs dav-parse crate is for outbound storage listings and is not reused as an inbound server.

## Backend boundary

A future adapter must authenticate each request with server-auth::app_passwords::verify_dav, use server-account sharing and server-store state, and return a tenant identity tied to a live app-password credential. allowed() must recheck credential revocation, user disablement, per-user sharing scope, Diary enablement and server-held local storage. The handler calls it after authentication, after reading write bodies, and before each PROPFIND row. All list/read/write/mkdir calls must bind to that authenticated user and recheck live authorization at the operation boundary; writes must make that check atomic with the versioned mutation. Backend list must cap allocation at 1024 direct children, and read must cap file content before allocation. The adapter must use Diary's guarded workspace operations for writes and never manipulate the corpus directly. In particular, it must reject symlinks at every path component and use the existing Trash/protected-path/version contract. This crate never opens a filesystem path; the synthetic backend simulates a symlink refusal. A future adapter must also audit mutations without recording credential or content bytes.

Backend futures are awaited in the request task. No detached operations are started. Dropping a request cancels the future; timeout of an in-flight write/MKCOL is reported as an ambiguous 503 with Retry-After: 5, so clients read again before retrying. An adapter must not continue a mutation in a detached task after cancellation.

## HTTP surface

The Config constructor accepts one clean HTTP(S) origin. Public scope requires HTTPS. HTTPS requires an exact 32–64-byte lowercase-hex proxy token plus X-Forwarded-Proto: https, and the exact Host authority is checked first. The token is compared in constant time. Duplicate Host, Authorization, proxy-token, forwarded-proto and conditional headers are refused. The transport caller must supply the real socket IP; forwarded client-IP headers never change the 120/minute per-IP budget. Up to four authenticated requests are active. The in-memory rate table is capped at 4096 peers, prunes expired peers at capacity, and fails closed if still full; production integration should add operational observation before activation.

Only /dav/<username>/ paths are accepted. Each percent-decoded segment must be UTF-8 and exclude empty interior, dot-leading, slash, backslash, percent and controls; URL length is at most 2000 bytes and tenant-relative path at most 500 bytes. Backend entries are checked as direct children with the same path rules. The server never resolves a local path itself.

HEAD suppresses all response bodies, including errors. GET and HEAD return UTF-8 Markdown, strong ETag and matching Content-Length; conditional GET supports If-None-Match. PROPFIND accepts Depth 0/1 and a narrow allprop/named-property XML dialect: 8 KiB body, at most 128 nodes, depth 8, no DTD/entities/processing instructions/custom attributes or text. Listings stop at 100 children, responses at 1 MiB, and operations have a 45-second default deadline. PUT accepts only .md, UTF-8 and up to 512 KiB; it requires exactly one strong If-Match or If-None-Match: *, and the backend performs the version compare atomically. MKCOL is available only when Backend::capabilities explicitly enables it, with an empty body and no conditions.

DELETE, MOVE, COPY, LOCK, PROPPATCH, REPORT, unconditional PUT with Trash preservation, directory ETags, and DAV class-1 advertisement are intentionally absent. They answer 405 or 428 and are not in Allow; future work must pair the existing Diary guarded operation contract and synthetic parity tests before enabling them. This crate is therefore a bounded independent source leaf, not a substitute for the current application listener. No listener should be wired or port exposed until a production adapter and independent paired qualification pass.
