# Inbound Diary sharing

`bins/noevia-server/src/dav.rs` owns the optional dedicated listener and implements this crate's backend using the existing signed Diary API. It does not delegate requests to the legacy application runtime or activate the experimental direct corpus backend.

The listener preserves the configured sharing scope, authority, HTTPS proxy verification, device app-password authentication, per-account opt-in and local-storage requirement. It binds `COWORK_DAV_HOST || UI_HOST || 0.0.0.0`, applies the code-network guard before authentication, and uses 15-second headers, 60-second request reception and socket inactivity, and the original keepalive behavior. Native account verification updates last-used only after the hash and live account are rechecked. Eligibility is checked again after write bodies and before each signed operation; no database lock spans a network await.

The handler supports OPTIONS, HEAD, GET, PROPFIND, PUT, MKCOL, DELETE, MOVE and COPY. Guarded Diary operations retain protected paths, versions, reversible replacements and Trash. Unconditional PUT preserves the previous bytes before a versioned replacement. Directory ETags, DAV class 1 and mutation audits are retained. The existing Diary client bounds response bodies; PROPFIND retains the 100-child limit. Backend entry paths are already decoded and must not be parsed again as URLs.

`bins/noevia-server/tests/dav_listener.rs` exercises synthetic accounts and a signed loopback Diary, including the committed Node response oracle, revocation during a pending body, code-network refusal, transport deadlines and encoded paths. `tests/http.rs` also covers backend cancellation and the shared handler's negative contracts. Release assembly and the supervisor require matching Core retirement and compiled native capability markers before starting a pair.
