# Diary workspace transaction engine

This crate is an opt-in source implementation. It is not connected to the Diary service. It requires an existing SQLite database opened in READ_WRITE mode (never CREATE), sets synchronous FULL, validates tenant/active/schema and a pre-existing canonical `workspace_operation_namespace`, then holds `BEGIN IMMEDIATE` across receipt lookup, validation, writes, and commit. The transaction CLI does not migrate or repair schema. Synthetic tests may provision `workspace_operation_receipts`; production schema migration and backup/restore integration remain held for separate review.

Schema admission uses the frozen managed-store application tables (`files`, `directories`, imports, outbox, `meta`, and passive `backups`) plus the separately proposed receipt table. It checks declaration grammar and actual column type/nullability/default/PK/hidden-column metadata, a single BINARY primary index, and absence of foreign keys, extra application tables/indexes, views or triggers. Known identity metadata is bounded before loading and invalid metadata types refuse. These checks precede receipt disclosure as well as new operations. Quoted/case-varied identifiers, comments, table-level single-column primary keys and equivalent literal integer defaults are supported. This is a bounded known-layout validator, not a general SQL parser. It never repairs or migrates a database and never updates backup records. The proposed receipt table/namespace still require separate production migration approval.

`tests/generate_schema_fixture.py --source /path/to/frozen/managed_storage.py` requires CPython3.12.15 and the frozen source hash, extracts the actual CREATE script and uses only in-memory SQLite. Its fixture does not claim that the old Python store already has a receipt table. Wrong source/interpreter controls must refuse before output changes.

Mutating requests require caller-persisted canonical `operationId` and `operationNamespace` values before opening the database. Immutable path/capsule shape is checked at that boundary; a well-formed namespace is then compared transactionally with stored identity. The durable namespace and tenant are part of the versioned semantic fingerprint, together with normalized paths and omitted/null/value condition identities. Live config, clock, debounce and the DB pathname are excluded. A matching ID/fingerprint returns the exact sealed payload before checking live path, config or ETag state; a different fingerprint returns 409 without replacing the original receipt. Public reply fields are immutable and exposed through read-only accessors. The canonical payload is bounded and sealed before receipt insertion/commit, and replay uses those same stored bytes. Stored response metadata is bounded before loading the BLOB; malformed/noncanonical receipts refuse without repair. Closed operation-specific status/body/identity checks run before a fresh commit and before cached replay. Trash/restore permit only their actual terminal conflict/capacity refusal domain. New Trash timestamps bind the original stored receipt creation time, not the retry clock. These are consistency checks, not authentication of an arbitrary attacker-authored database; complete engine/runtime qualification remains pending.

This source interprets the stable-outcome contract to include ordinary terminal policy refusals after valid identity/DB/namespace checks. A savepoint rolls back every attempted operation effect before committing only the sealed refusal receipt; generation and outbox remain unchanged. Same-ID retry replays that refusal even after live state changes; a deliberate new attempt requires a new caller-persisted ID. Malformed request/identity, schema/tenant/namespace, infrastructure or internal faults are not cached. This interpretation must be covered by complete source review; it is not a claim that the original approval explicitly singled out refusal receipts. The engine is still an incomplete source WIP.

Replies preserve the recorded `alreadyApplied` field, even where the old Python Trash retry path reported `true`. `capsuleId` is separate from `operationId`; restore needs a new operation ID. This does not give an HTTP/DAV caller exactly-once behavior until it can persist and resend the same IDs.

Transport uses `DWT1`, a little-endian u32 JSON byte length (maximum 2 MiB), strict JSON request schema and EOF. Framed replies use `DWR1`, little-endian u32 JSON length (maximum 1 MiB), JSON, `END1`, and EOF. A malformed/unavailable request emits no success frame and exits nonzero; ordinary policy refusals are framed outcomes. If writing or flushing the response fails after execution, the CLI exits 3 and the result is uncertain: only retry with the same persisted identity can resolve it. The CLI source guarantees transaction-level SQLite atomicity only. The caller must enforce its deadline and kill/reap the process while retaining its locks; source code alone proves no cancellation or process lifecycle guarantee.

The service adapter must still prove account authorization before creating an AppState/root or opening tenant storage; the cross-service account DB and Diary lock order must be designed and reviewed. Today the Diary store._write_lock and managed.migration_lock() are process-local RLocks: an external CLI process and BEGIN IMMEDIATE cannot fence journal append/replay, tenant deletion, root removal, or restore. Stage 2 needs a reviewed cross-process tenant fence or Diary-owned IPC/quiescence, with global core-account-before-Diary lock order. The adapter would need to hold its real exclusion through child exit/reap. This CLI alone does not prove child-death behavior, timeout cancellation, credential revocation, HTTP/DAV authorization, or a production auth fence. No selector or service call path is enabled here.

A future full backup format must snapshot the receipt rows and operation namespace atomically with the files, directories, settings, and generation. Portable exports are not equivalent. Restore should stage a new DB, preserve archived receipts for audit, rotate the active namespace/incarnation, and require callers to bind IDs to the namespace so post-snapshot IDs cannot be replayed after restore. That migration and restore policy are not implemented here.

## Reproduce the source contracts

Use CPython **3.12.15 / Unicode 15.0.0** with its default 4,300-digit integer conversion limit and the test dependencies from the frozen services source. The generator requires its `fastapi.HTTPException` type but never starts FastAPI, the Diary app, network clients, journal workers or models. Pass a local checkout containing the exact hash-pinned `diary/agent` files; every source checksum is verified before definitions execute or temporary SQLite stores are constructed.

```sh
python tests/generate_contract_fixtures.py --source /path/to/frozen/noevia-services --check
python tests/check_contract_fixture_generator.py --source /path/to/frozen/noevia-services
python tests/generate_schema_fixture.py --source /path/to/frozen/noevia-services/diary/agent/managed_storage.py --output /tmp/managed-schema.json
```

The first command independently computes 24 read, 135 mutation and 18 Unicode ordering cases, then compares all output bytes. It reads checked-in goldens only at the final comparison and does not invoke, inspect or build Rust. Omit `--check` to regenerate, or use `--output-dir` to stage results elsewhere. Generation completes in memory before any artifact is replaced; each file replacement is atomic. An output I/O failure can leave a partial set, so use `--check` after writing. Wrong source/interpreter and unexpected operation failures produce no expected fixture updates. The explicit checker is not an automatically discovered Python test: it requires a frozen source argument.

`oracle_inputs.py` contains only synthetic input specifications. `oracle_source.py` compiles actual selected backend/class methods and operation functions from verified AST nodes, excluding module imports/startup. Expected success bodies and complete listed SQL state digests come from those functions. Error vectors compare statuses; they do not prove matching HTTP error bodies. Fixed time, locale and UUID providers are explicit fixture inputs; the deterministic delete UUID provider follows the separate DWT1 identity contract and does not qualify Python's random UUID algorithm. The legacy schema fixture is generated separately and excludes the proposed native receipt table. Source fixtures prove kernel behavior for recorded profiles, not authorization, process cancellation/reap, index draining, runtime adoption or full backup/restore.

## Operation and data profile

| Operation | Immutable inputs and conditions | Successful body |
| --- | --- | --- |
| `stat` | `source`, configured corpus root | `path`, `isDir`, `version`, `entries` |
| `list` | Optional `source` (empty means corpus root), configured root | Array of `path`, `name`, `isDir`, optional `modified` |
| `trashList` | Optional `limit` (1–100), optional UUID `cursor` | `records`, `next`; records failing capsule decode remain visible as sentinels |
| `delete` | `source`; source ETag required when an existing source is evaluated | `deleted`, distinct `trash` capsule IDs |
| `move` | `source`, `destination`; source ETag, conditional replacement ETag/capsule | `path`, `destination`, `replaced` |
| `copy` | `source`, `destination`; source condition if supplied, conditional replacement ETag/capsule | `path`, `destination`, `replaced` |
| `preserve` | `source`, source ETag, `capsuleId` | `path`, `trash` |
| `trash` | Raw safe Markdown `source`, its version, `capsuleId` | `id`, `path`, `version`, `state`, `trashedAt`, `alreadyApplied` |
| `restore` | `capsuleId`; restore target comes from validated capsule metadata | Same summary fields as `trash` |

`operationId` is a mutation receipt identity, not a capsule identity. Omitted/null/value conditions remain distinct in the fingerprint. An existing replacement requires explicit overwrite, its ETag and a capsule ID; merely requesting overwrite when the destination is absent does not require a replacement capsule. Live path/config/clock checks do not run again for a valid same-identity receipt. Mutation identity fields listed above still participate even when unused by that operation, so retries must preserve them. Pagination fields belong to read-only calls and are not mutation identity.

Relevant mutation subtrees admit at most 500 file/directory entries and 50 MiB before loading bodies. Capsule raw files are at most 512 KiB; encoded legacy capsules are bounded to 1 MiB, JSON depth 32 and 10,000 nodes. Derived transfer targets are checked before writes against both the 500-codepoint relative-path and 4,004-byte backend-key domains. Unlike the legacy implementation, unsafe overlong derived outputs refuse with capacity rather than committing unreadable paths. No value is truncated or repaired.

Metadata listing reuses static Unicode15 lowercase/final-sigma rules and stable sorting. Markdown suffix checks use ASCII lowering: exhaustive pinned-scalar evidence establishes that only ASCII dot/M/m/D/d can contribute to the `.md` suffix. SQLite tie-order profiles and Linux/runtime qualification remain separate from this lowercase proof.

Replies expose lossless `Json`/`JsonNumber` values, including integer text. `to_value()` is a checked convenience view that refuses integers outside serde's exact integer domain. Bounded streaming output uses sorted keys and pinned Python finite-float spelling; cached replay parses and validates the same canonical encoding. This unpublished encoding is not a migration of deployed receipts. Integer tokens, including ones discarded by later duplicate keys, obey the pinned CPython 4,300-digit limit. Unknown capsule data remains in its original encoded representation through validation and lossless restoration; opaque nonfinite metadata is not emitted as reply JSON. Selected nonfinite timestamps, lone surrogates and other corrupt/exotic profiles do not receive blanket parity or runtime qualification.

Persisted generation counters use canonical nonnegative decimal text within that pinned conversion domain. Malformed/noncanonical counters and nonfinite clock arithmetic refuse without partial metadata writes. Ordinary valid terminal refusals roll back operation effects and store only their receipt; infrastructure/internal/schema faults do not become terminal policy results. CLI atomicity, semantic source checks and component fixtures do not retire the Python owner or complete the held caller/migration/lifecycle/backup/sink gates above.
