# Offline Diary operator support

`diary-backup-restore BACKUP_ROOT MANIFEST_JSON NEW_DIRECTORY` verifies a downloaded
immutable backup and restores only into a new directory. It never chooses a latest
manifest, contacts a server, or overwrites an existing destination. Payloads are
verified before creating the destination. Each file is created exclusively, flushed,
and fsynced. Like the original operator, a filesystem failure during materialization
can leave a partial new destination; it does not rename a staging directory or fsync
parent directories.

`diary-config [CONFIG_YAML]` prints the resolved configuration for offline diagnosis.
It applies environment overrides in their original order, including the legacy
CORPUS_REMOTE_ROOT alias. Configuration output can contain credentials; treat it like
the source configuration. The library also exposes open-mode policy and prompt-file
loading for the future standalone server. This command does not start a server.
DIARY_CONFIG_DIR selects the installed config directory (default `/app/config`).

The Python service still imports its original config and restore modules. Those stay
until their consumers move. Runtime exceptions print the Python exception class and
message; interpreter stack frames are not generated by the native executable.

`tests/oracle.py` freezes a Python reference into a caller-supplied evidence directory
outside the checkout, then replays the same synthetic filesystem cases against the
native executable. It compares exit codes, stdout, the final exception line, file
bytes, directories and modes; full Python stderr is retained separately. The oracle
extracts only safe_key to avoid importing storage/runtime initialization. The config
oracle similarly imports only config.py. Neither harness starts or contacts a server.
