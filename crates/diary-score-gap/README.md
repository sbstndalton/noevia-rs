# Diary score gap (#1071)

Pure foundation extracted from `noevia-services/diary/agent/score_gap.py` at
`6c1eb5891c75b6fb9f04c4484ba39da80a5b4b9e`. This crate is not yet wired to
production and does not retire Python code. The bounded CLI is available as the same-package binary `diary-score-gap`. A paired
host adapter, host failure policy, Docker build and pinned cross-repository CI remain.

`cut` consumes normalized optional scores and a parsed optional gap. It returns
stable input positions and the maximum finite score. Python retains `float`
coercion (including numeric strings/bools), warning-once config parsing, original
rank/row objects and trace refs. Nonfinite scores act as missing scores.

Call after entity focus removes time-ineligible candidates. The current caller
suppresses the gap only when its actual focus result contains entities; a time
anchor alone does not suppress it. If entity focus is disabled, named questions
can still use the gap. Disabled gaps still compute `best`. Trace `applied` is a
caller policy flag, not a count of removed candidates.

Tests compare 352 committed synthetic vectors generated by the actual source
Python `cut`, including signed zero, missing/NaN/infinite scores, unsorted input,
epsilon boundaries and disabled gaps. Regenerate using `tests/generate_fixtures.py`
and the source path, then review the fixture diff. Python is not needed to run
the Rust fixture tests. No Diary text, credentials, models or storage are involved.

## CLI protocol v1

No arguments. Stdin is exactly one UTF-8 record followed by EOF:

```text
diary-score-gap-v1<TAB>gap<TAB>scores<LF>
```

`gap` is `null` (disabled) or a finite decimal float in `(0, 1]`.
`scores` is an empty field (zero candidates) or comma-separated tokens, each
`null` or a finite decimal float. The host must normalize missing/nonfinite
scores to `null` and perform Python score coercion first. Numeric tokens contain
only ASCII digits and decimal/exponent punctuation `.+-eE`, must contain a digit,
and must parse completely as Rust `f64`; NaN, infinity, whitespace and overflow
are rejected. There are no text, object, ID or rank fields.

Input is at most 131072 bytes including LF, with at most 4096 scores.
Exactly three tab-separated fields are required. CRLF, missing LF, extra records,
trailing bytes, bad versions, invalid UTF-8 and trailing comma are rejected.
The process reads at most the byte limit plus one before rejecting oversize.
It waits for EOF, so the host must close stdin and enforce a process timeout.

Successful stdout is exactly:

```text
diary-score-gap-v1<TAB>best<TAB>kept_positions<TAB>removed_positions<LF>
```

Best is `null` if no finite score exists, including empty input; otherwise it
is a round-trippable finite decimal float (signed zero is retained). Positions
are zero-based decimal integers separated by commas, with empty fields for empty
lists. The stable partition covers each input position exactly once. With the
count limit, a valid response is below 32768 bytes.

Exit 0 means success with empty stderr. Exit 2 means invalid input/arguments,
empty stdout and fixed `invalid request\n` stderr. Exit 3 means input/output
failure with fixed `io failure\n` stderr; stdout may be incomplete. The host
must reject all nonzero exits, malformed/oversize responses, incorrect version,
invalid best values, out-of-range/duplicate/unordered positions, or a partition
that fails to cover the original list. It must cap output and validate the
complete record plus EOF before using any indices. Host timeout, executable
selection and fallback policy belong to the later services adapter. This CLI
does not activate a selector or retire Python.
